# 燎原 v1 设计记录

目标管理 + 增量游戏的可试用原型，由《野火》扩展而来。「燎原」是暂定名。这是「养一只」之前的版本（森林题材），因美术和题材偏老气被替换；规则思路（回来要便宜、只奖励真实行动）沿用到了「养一只」。

- 日期：2026-11-13
- 已定的方向：网页应用；先中文，文案和模型接口留好切换；先做原型验证钩子，再投入正式工程。
- 本仓库不含燎原的代码，只保留这份记录。

## 核心判断

问题不是缺动力，而是中断后「回来的成本太高」（愧疚、冷启动、看不到进展）。所以不防中断，而是让回来变便宜、有奖励。

## 规则（引擎 engine.js，纯函数，时间由外部传入）

- **种子**是唯一入口，只能靠记录真实推进获得。没有任何可空刷的操作。
  - 自报的量：一点 1 / 一段 2 / 一大块 3
  - 留下「下一步」+2，回答一句追问 +2（大头给「留下东西」）
  - 同一天第 2 次减半，第 3 次起固定 1 粒
  - 立项并写下第一步，送 3 粒
- **植物**：青苔、野草、蕨、灌木、乔木，种子价 1/2/4/7/12，每小时产 1/3/9/25/70 养分。每种最多 20 株，到 5、10、20 株各翻倍。按这个目标的累计养分解锁（100 / 2,000 / 3 万 / 40 万）。
- **水 = 下一步**：每次推进把溪水续满（默认 3 天），没留下一步只续一半。水停了只是暂停生长，什么都不会枯死。养分可以引溪流，每级多流 1 天。
- **枯落层 = 回归加成**：离开 d 天后第一次推进，种子 × (1 + 0.5·√(d−1))，30 天封顶。模拟确认按天平均后单调下降，故意不来永远不划算。
- **野火 = 里程碑**：一段做完就放火，坡上植物烧掉，按这一段养分的平方根换灰烬。之后 3 天新灰期产量 ×2。建木每长一段，本目标产量 ×1.5。
- **灰烬跨目标永久保留**：没用掉的每份 +4% 产量，可换 4 个根系（余烬、深潭、厚落叶、好种）。
- **放弃有出口**：烧掉目标，灰照拿，记入归档。
- 同时只有一个进行中的目标。

## 大模型用在哪（都由用户点击触发，都有不联网的兜底）

1. 立项：把目标拆成 3–5 段，并给出 20 分钟内能做的第一步
2. 追问：记录推进后问一句具体的问题，回答存为笔记
3. 接风：离开 ≥2 天回来时，根据记录写三句话（上次到哪、当时卡在哪、今天最小一步）
4. 切小：把下一步切成 3 个十分钟版本
5. 灰烬卡：阶段结束时根据记录写小结

## 结构

- `Store`：存档适配器（Claude 账号云端优先，浏览器本地兜底）
- `AI`：模型适配器（现在走 Claude，换别家只改这里）
- `LANGS`：文案与提示词按语言分表
- 设置里有「把时间往后拨」，用于试用离开再回来的流程

## 已知的缺口

- 没有推送提醒：解决不了「忘了」这一种中断
- 数值只经过模拟（7 种节奏 × 60 天），没有真人数据
- 云端存档和 Claude 调用只用替身测过，未在真实环境验证
- 付费墙、账号体系、多目标都没做

## 下一步要回答的问题

用一个真实目标试用一到两周，看：断掉之后有没有回来；是接风还是枯落层起了作用；追问是否嫌烦；哪些数值不对劲。
